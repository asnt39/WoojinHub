# 우리오 v22 — 럭키박스 접근성과 체크포인트 부활 수정

작성: 2026-11-05 (KST)

## 재현된 원인

- v21의 계단형 벽돌은 물리적으로 밟을 수 있었지만 럭키박스의 양옆을 낮은 벽돌로 막았다. 따라서 아래에서 점프해 상자를 활성화할 수 없는 배치가 있었다.
- 후반 맵의 추가 벽이 일부 럭키박스 바로 아래까지 겹쳐 접근을 더 막았다.
- 지면 높이는 가변적으로 바꾼 반면 사망 후 부활 `player.y=370`은 고정했다. 높아진 지면에 플레이어가 처음부터 겹쳐 생성되면 착지 판정이 성립하지 않아 그대로 바닥을 통과했다.
- 체크포인트 깃발 시각 요소도 기존의 고정 y좌표를 사용했다.

## 수정

1. 계단 세 개는 왼쪽에 유지하고 럭키박스는 통로를 두고 오른쪽에 별도로 배치했다. 각 상자는 아래에서 점프해 활성화할 수 있으며 모든 벽돌에 올라설 수 있다.
2. 후반 스테이지 벽은 럭키박스가 있는 지면 구간에 겹쳐 생성되지 않도록 분리했다. 이에 따른 가시 수 감소를 방지하도록 별도 접근 가능한 구간에 가시를 배치했다.
3. 모든 스테이지에서 높낮이 있는 지면, 벽돌, 가시, 적, 톱날을 피하는 실제 체크포인트 부활 좌표를 선정한다. 사망 후 해당 지면의 윗면에 캐릭터를 배치한다.
4. 체크포인트와 출구 깃발도 각각 설치된 지면 높이에 맞춰 그린다.

## 자동화 검증

- 새 `tests/adventure-v22.cjs`: 각 스테이지의 모든 럭키박스 아래 서 있을 공간과 접근 통로를 검사하고, 8개 스테이지 각각에서 실제 이동·점프 입력을 보내 첫 럭키박스를 활성화하는 봇 테스트 통과.
- 동일 테스트: 각 스테이지에서 실제 체크포인트를 활성화하고 사망·전환·재부활 이후 180프레임 동안 캐릭터가 지면 위에서 살아 있는지 검증. 실제 적·가시·톱날을 유지한 상태에서 통과.
- 기존 우리오 v20·v21 및 8개 월드 구덩이 점프 시뮬레이션 통과. GTW·합치기·사진·허브 UI 관련 비브라우저 회귀 테스트 통과.
- 로컬 브라우저에서 바뀐 계단과 럭키박스 사이 공간을 육안 확인.

## 남은 한계

- 모든 럭키박스의 정적 접근 공간은 검사했지만 실제 봇의 점프 활성화는 스테이지당 첫 럭키박스에 대해 수행했다.
- 몬스터·톱날이 있는 맵 전체를 자동으로 완주하는 AI 검증이나 Android 장시간 성능 계측은 수행하지 않았다.
- 기존 브라우저 자동 테스트 중 일부는 실행 환경에 Chromium 실행 파일이 없어 실행할 수 없었다.
