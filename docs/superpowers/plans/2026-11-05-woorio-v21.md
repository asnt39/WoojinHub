# Woorio v21 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or the native TDD workflow to implement task-by-task.

**Goal:** Ship an actually playable, vertical eight-world Woorio with a final boss, reliable death/reset behavior, and polished touch UI.

**Architecture:** Extend existing static `dist/adventure.js` world builder and physics/render loop in place, with a small boss controller and same persistent progression contract. Extend existing `PixelArt` sprites and adventure-specific styles; touch no other game logic.

**Tech Stack:** Vanilla JS canvas 2D, CSS, Node `vm` + `@napi-rs/canvas` tests.

**Spec:** `docs/superpowers/specs/2026-11-05-woorio-v21-design.md`

## Global Constraints

- Keep `woojin-adventure-v1` storage and eight stage indices.
- Do not modify the remaining three games.
- Do not conflate generated levels' structural path test with actual human playtesting.

## Review Focus

1. Spawn on elevated terrain remains supported and visible.
2. Blocks near holes do not overlap pits, create completely enclosed rewards, or make unavoidable hazards.
3. Death while giant destroys no more spikes after death triggers; reset boxes and items correctly.
4. Boss fight cannot be skipped; special attacks cannot hit from outside the arena and must be re-acquirable.
5. Touch button pointer release on different controls never leaves a key stuck.
